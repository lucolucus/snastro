# llama-jni-libreria — Libreria llama-jni: binding JNI di llama.cpp b11195, API neutra, test sul NativeBridge finto, nativi macOS arm64 (ADR 0027)

## What to do
Create the separate library :llama-jni (./llama-jni/, package io.github.lucolucus.llamajni, ADR 0027 §1) with zero snastro dependencies: settings include and the allowedModuleEdges row ":llama-jni" to emptySet(); its own build script (public plugins only, explicit API, own detekt config); the portable C11 JNI shim and the vendored b11195 llama.cpp/ggml headers; the internal NativeBridge seam behind every external fun; the public API pinned by boundary tec-llama-jni (LlamaJni.load(nativeDir), LlamaBackend.devices/openModel, ModelParams, LlamaModel.countTokens/generate/close, GenerateOptions, Generation, StopReason, LlamaResult/LlamaError); unit tests over a fake NativeBridge inside the gate; the opt-in :llama-jni:nativeTest with a pinned tiny GGUF (URL + SHA-256 + licence pinned by this block); README.md, THIRD-PARTY-NOTICES and LICENSE (MIT); the native tasks downloadLlamaNatives / compileJniShim / assembleNatives for macOS arm64 only, outside check, cached in <Gradle user home>/caches/llama-jni/b11195/. ADR 0027's check applies from this block.

Note: Split 2026-09-26 from modello-linguistico-llama (ADR 0027, user; D-0007). Owns boundary tec-llama-jni (the pinned public API). Mac only for now (Q-1): Windows x64 / Linux x64 wiring is llama-jni-windows / llama-jni-linux (R4, not ready). Everything under llama-jni/ is laid out so it can later become an included build or its own repo with NO edit inside it (no rootProject/rootDir/../, no snastro plugin, no snastro.* in code). The Qwen-based contract and the Riassunto NFR are NOT here (modello-linguistico-llama). GATE_FILES NOTE (for the composer/architect, the profile is not edited here): the profile's gate_files cover llama-jni/build.gradle.kts via '*/build.gradle.kts' but NOT llama-jni/config/** (the library's own detekt config) nor a llama-jni properties file pinning the asset/GGUF — add 'llama-jni/config/**' (and 'llama-jni/*.properties' if used) so a change there makes the gate proof stale.

**ready_when:** SATISFIED 2026-09-26 — ADR 0027 accepted; user answers Q-1 (Mac only for now), Q-2 (MIT), Q-3 (llama-jni / io.github.lucolucus.llamajni), Q-4 (Vulkan + CPU fallback, no Windows/Linux NFR) recorded as D-0007.

## Tasks
- AC-S164 (native half of AC-S156, split 2026-09-26 by ADR 0027) The library's own build script defines downloadLlamaNatives, compileJniShim and assembleNatives for macOS arm64 ONLY: downloadLlamaNatives fetches the pinned b11195 '…-bin-macos-arm64' asset into <Gradle user home>/caches/llama-jni/b11195/ (URL + SHA-256 pinned once inside llama-jni/, never in the root version catalogue; a mismatch fails the task and deletes the file) and extracts only the pinned library list; compileJniShim builds libllamajni.dylib (clang -O2 -shared, rpath @loader_path, JNI symbols Java_io_github_lucolucus_llamajni_…); assembleNatives writes both to llama-jni/build/natives/macos-arm64/; on any other host the three tasks fail with a message naming ADR 0027 Q-1 (not wired); none is a dependency of check (`./gradlew check --dry-run` lists none of them, and the gate needs no C compiler, no native, no download); ADR 0026's check (no GGUF / llama.cpp archive tracked) exits 0
- AC-S165 (generic half of AC-S159) Fake NativeBridge, inside the gate: GenerateOptions.maxTokens is handed to the native generation and a bridge that stops at the limit maps to Generation.stop = StopReason.MAX_TOKENS (END_OF_GENERATION otherwise); a non-null grammar is passed to the bridge with its grammarRoot and lazyGrammar = true by default; a bridge grammar-parse failure → Err(GrammarInvalid(detail)) with no decode
- AC-S166 (generic half of AC-S160) Fake NativeBridge, inside the gate: the overflow check runs BEFORE any decode — promptTokens + maxTokens = nCtx − 1 and = nCtx proceed; = nCtx + 1 → Err(ContextOverflow(promptTokens, maxTokens, nCtx)) with ZERO decode calls recorded on the bridge
- AC-S167 (library cancel mechanics of AC-S152) Fake NativeBridge, inside the gate: prefill is issued in prefillChunk-token decodes (a 1 300-token prompt with prefillChunk 512 → 3 decodes); a watcher polls cancel() and sets the native abort flag; cancel() true before the first decode → Err(Cancelled) with no decode; cancel() turning true while the bridge blocks on a latch → the abort flag is set, and Err(Cancelled) is returned only AFTER the bridge call has returned (asserted by ordering)
- AC-S168 (library side of AC-S157) Fake NativeBridge, inside the gate: LlamaModel.close() frees context then model; a second close() makes no bridge call; countTokens/generate after close → Err(Closed); with two open models llama_backend_free is called exactly once, after the LAST one closes; LlamaJni.load(nativeDir) is idempotent per JVM (second call loads nothing) and reads no system property
- AC-S169 (NEW) UTF-8 round trip, inside the gate: text crosses the bridge as standard UTF-8 byte arrays — countTokens/generate hand the bridge exactly String.encodeToByteArray() bytes; generated pieces are accumulated as bytes and decoded once, so an Italian accented text, a supplementary character (emoji U+1F600) and a multi-byte character split across two token pieces come back identical; the C shim never calls GetStringUTFChars/NewStringUTF on model text (grep over llama-jni/src/main/c)
- AC-S170 ModelParams and load plan, inside the gate: nGpuLayers < 0 (other than ALL), nCtx ≤ 0, nUbatch ≤ 0, prefillChunk ≤ 0 or prefillChunk > nUbatch are rejected in Kotlin with no bridge call; defaults prefillChunk = 512, grammarRoot = 'root', lazyGrammar = true; the macOS arm64 load plan loads the shim only (rpath resolves the rest) with dynamic backends OFF; LlamaBackend.devices maps the bridge's list (name, kind CPU/GPU, free/total memory); every bridge failure maps to its LlamaError (NativeLoadFailed, ModelLoadFailed, ContextCreateFailed, DecodeFailed(code)); no LlamaError is a Throwable (CR-8)
- AC-S171 (NEW, opt-in, outside the gate) `./gradlew :llama-jni:nativeTest` (JUnit tag `native`) on the Mac against the real natives and a tiny public GGUF pinned in llama-jni/ by URL + SHA-256 + licence (candidate ggml-org stories260K.gguf; downloaded to the cache, never tracked): 20 openModel/close cycles with RSS after cycle 20 within +10 % of RSS after cycle 1; countTokens deterministic over 3 calls; output accepted by a small GBNF; MAX_TOKENS stop; ContextOverflow with no decode; Cancelled before the first decode and mid-generation, returned within 10 s; devices lists a GPU (Metal) device; the run prints PASS and exits 0
- AC-S172 (NEW) llama-jni/README.md (purpose, public API, build tasks, per-OS requirements: macOS arm64 wired; Windows x64 / Linux x64 pending the build-host decision, ADR 0027 Q-1), llama-jni/THIRD-PARTY-NOTICES (llama.cpp / ggml MIT, 'Copyright (c) 2023-2026 The ggml authors') and llama-jni/LICENSE = MIT (user, Q-2, D-0007) exist; ADR 0027's check architettura-test/controlli-adr/adr-0027-libreria-llama-indipendente.sh is applicable (llama-jni/build.gradle.kts and llama-jni/src/main/kotlin exist) and prints 'ADR-0027 libreria-llama-indipendente: PASS', exit 0, and runs in ControlliAdrTest with a conforming and a violating fixture per rule (project(/rootProject/../ in build; snastro. in code, not in comments; Java_snastro_ symbol)
- AC-S173 Module wiring: settings.gradle.kts includes ':llama-jni'; allowedModuleEdges gains ":llama-jni" to emptySet() (and nothing else in this block); llama-jni/build.gradle.kts applies public plugins only (Kotlin JVM, detekt), explicit API mode, allWarningsAsErrors, JUnit 5, its own detekt config under llama-jni/config/; its only runtime dependency is the Kotlin stdlib; `./gradlew check` runs :llama-jni:test; a throwaway edge :llama-jni → :kernel makes verificaDipendenzeModuli fail (proved in the block, not committed); ADR 0004's check (native loading only in ml-sherpa and ./llama-jni/) and ADR 0006's check (deny-list names llama-jni) exit 0

## Dependencies
- **tec-llama-jni** (OWNED — this block publishes it; consumers modello-linguistico-llama, llama-jni-windows, llama-jni-linux; projection in-process; contract_test `consumer-driven`)
  - `LlamaJni (io.github.lucolucus.llamajni)`: object { fun load(nativeDir: Path): LlamaResult<LlamaBackend> } — explicit directory, reads NO system property, no default location; idempotent per JVM; initializes the llama backend (dynamic-backend platforms: ggml_backend_load_all_from_path(nativeDir))
  - `LlamaBackend`: interface { val devices: List<BackendDevice>; fun openModel(model: Path, params: ModelParams): LlamaResult<LlamaModel> }
  - `BackendDevice`: data class(name: String, kind: DeviceKind, freeMemoryBytes: Long, totalMemoryBytes: Long)
  - `DeviceKind`: enum { CPU, GPU }
  - `ModelParams`: data class(nGpuLayers: Int /* ModelParams.ALL | 0..n */, nCtx: Int, nUbatch: Int, prefillChunk: Int = 512, flashAttention: FlashAttention = FlashAttention.AUTO) — validated in Kotlin before any native call (positive values, prefillChunk ≤ nUbatch)
  - `FlashAttention`: enum { AUTO, ON, OFF }
  - `LlamaModel`: interface : AutoCloseable { fun countTokens(text: String): LlamaResult<Int> /* exact, llama_tokenize with special-token parsing */; fun generate(prompt: String, options: GenerateOptions, cancel: () -> Boolean): LlamaResult<Generation>; override fun close() /* idempotent; frees context + model; llama_backend_free after the LAST open model */ } — blocking, thread-confined, one generation at a time per model
  - `GenerateOptions`: data class(maxTokens: Int, grammar: String? /* GBNF */, grammarRoot: String = "root", lazyGrammar: Boolean = true, sampling: Sampling = Sampling())
  - `Sampling`: data class of sampler settings (temperature, top-k/top-p, seed) — exact field set and defaults pinned by llama-jni-libreria in its README when built; additive thereafter
  - `Generation`: data class(text: String, promptTokens: Int, generatedTokens: Int, stop: StopReason, timings: Timings)
  - `StopReason`: enum { END_OF_GENERATION, MAX_TOKENS }
  - `Timings`: data class(loadMs: Long, prefillMs: Long, generationMs: Long) — exact field set pinned by llama-jni-libreria; additive thereafter
  - `LlamaResult`: sealed <T> { Ok(value: T); Err(error: LlamaError) }
  - `LlamaError`: sealed, NOT a Throwable (CR-8) { NativeLoadFailed(detail: String); ModelLoadFailed(detail: String); ContextCreateFailed(detail: String); ContextOverflow(promptTokens: Int, maxTokens: Int, nCtx: Int); GrammarInvalid(detail: String); Cancelled; DecodeFailed(code: Int); Closed } — misuse (e.g. a call from another thread) is a programming error (check), not a result
  - `NativeBridge (internal)`: internal interface behind every external fun — NOT part of the public API; the seam the library's unit tests fake
  - key `native directory / model path`: minted by the CALLER (snastro: :avvio's suppliers, ADR 0027 §7) — the library never derives a location
  - guarantees: overflow check before any decode (sum = nCtx proceeds); prefill in prefillChunk decodes, each a cancel point; Err(Cancelled) only after the native call returned; maxTokens enforced natively → MAX_TOKENS; lazy grammar; text crosses JNI as standard UTF-8 bytes (ADR 0027 §2)
