# Context map — snastro

> Project-level strategic trunk. AMENDED by every feature, never re-forked.
> Canonical terms are Italian (profile `ubiquitous_language.lang: it`). Each term is written as
> `Term` (schema/type name) = meaning. **One concept = one name.** The "Not:" lists name the
> synonyms that must NOT appear in code (verifier grep).

## Bounded context: Progetto
- **Role:** supporting — upstream (owns the project and its catalogue of recordings; scopes everything else)
- **Ubiquitous language:**
  - `Progetto` = a container the user opens and keeps feeding over time; it scopes the recordings AND the gallery of `Parlante`s (identities never cross projects). Not: workspace, cartella, sessione.
  - `Registrazione` = one audio file the user already recorded, added to a `Progetto` (source file + `titolo` + date of the recording + duration). `titolo` = the source file name without extension, fixed at import and **immutable** (user decision 2026-09-23); **unique per `Progetto`** — on a clash (compared on its file-safe, case-insensitive form) `AggiungiRegistrazione` appends " (2)", " (3)"… (user decision 2026-09-23), so the `Sbobinatura` file name is unique. It is the unit of processing and of output (one `Sbobinatura` per `Registrazione`). Not: audio, file, meeting, riunione, sessione, clip.
    *(amended 2026-09-30, feature `incontro` [user D-0001, D-0008])*
    - **Membership.** Every `Registrazione` is a `Parte` of exactly ONE `Incontro` of the same `Progetto`. Its `Incontro` is fixed **at import** and never changes (like its `Progetto`, INV-1). There is no gesture to attach, separate or move it. A `Registrazione` in the wrong `Incontro` is fixed by `Eliminare una Registrazione` and importing the file again.
    - **Scope.** It stays the unit of **processing** (`Elaborazione`, `Trascritto`, `Ritrascrivere`) and of the `Sbobinatura`. It is no longer the unit of the `Riassunto`, which belongs to the `Incontro`. Its `Voce`s are the `Incontro`'s (see `Voce`).
    - **Import.** `AggiungiRegistrazione` *(amended)* imports one or **several** files **into a target `Incontro`**. The target is either a new `Incontro` (created by that import, and all its files become its `Parte`s) or an existing one (its files are added as further `Parte`s). The `titolo` rules are unchanged.
  - `DataRegistrazione` = the date the recording took place (defaults to the file's date, user-editable); used to label `Parlante`s of type `occasionale` ("ospite del 12/09"). Not: data import.
    *(amended 2026-09-30, feature `incontro`)* Together with `OraDiInizio` it orders the `Parte`s of an `Incontro`. Changing it can therefore reorder an `Incontro`. The "Ospite del …" label now uses the date of the `Incontro`, which is the `DataRegistrazione` of its first `Parte`. For a 1-part `Incontro` this is the same date as today.
  - `OraDiInizio` *(added 2026-09-30, feature `incontro` [user D-0008, D-0009])* = the time of day the recording started. With `DataRegistrazione` it gives the instant that orders the `Parte`s of an `Incontro`. `DataRegistrazione` alone is date-only (`1.sqm`), so this needs a new value.
    - It is read from the file at import. Where it comes from, and the **automatic fallback** when the file gives none (every `Registrazione` imported before this feature included), are spike `ora-di-inizio`.
    - It is **user-editable**, like `DataRegistrazione` [user D-0009]: editing it is the way to fix a wrong order.
    - An edit of it (or of `DataRegistrazione`) that changes the order of the `Parte`s makes the `Incontro`'s `Riassunto` `superato`.
    - Not: timestamp, orario, data e ora di import, `aggiunta_alle` (that is the import instant, a different fact).
  - `Incontro` *(added 2026-09-30, feature `incontro` [user D-0001, D-0008])* = one real meeting inside a `Progetto`, recorded in ONE or more `Registrazione`s (its `Parte`s), ordered automatically by start (`DataRegistrazione` + `OraDiInizio`). An `Incontro` has **≥ 1** `Parte`.
    - **Forming.** The user forms it **by import only**: they create a new `Incontro` or open an existing one, and add files to it, several at once. An `Incontro` is created by the import that brings its first `Parte`s, so an empty `Incontro` never exists.
    - **Persistence and end.** It is persistent. It ceases to exist only when its last `Parte` is eliminated.
    - The `Incontro` scopes the `Voce`s (the "Voci dell'Incontro") and owns at most one shown `Riassunto`.
    - Its title and date are **derived, never stored or edited**: the `titolo` and `DataRegistrazione` of its first `Parte`, plus "· N parti" when N ≥ 2.
    - The migration creates one `Incontro` per existing `Registrazione`, and its `Riassunto` passes to it.
    - **A 1-part `Incontro` looks like a `Registrazione` today**: same screens, same data after the migration, no "parte 1" label. The one deliberate difference is D-0007: `Voce` numbers are never reused, and a `Ritrascrivere` makes the `Riassunto` `superato` (see `Ritrascrivere`).
    - Not: riunione, meeting, sessione, gruppo, raccolta, evento, cartella.
  - `Parte` *(added 2026-09-30, feature `incontro`)* = a `Registrazione` in its role inside its `Incontro`, with its **numero della parte** (1-based). The number is derived from the order at read time and never stored: an import into the `Incontro`, an elimination or an edit of `DataRegistrazione`/`OraDiInizio` can change it. It is a role, not a second entity: the type stays `Registrazione`, and no `Parte` type duplicates it. Shown as "parte 2", and in a `Fonte` as "parte 2 · 12:30". Not: spezzone, pezzo, traccia, file, capitolo (reserved for the out-of-scope chapters), segmento (taken).
  - **Out of scope (feature `incontro` [user D-0008], supersedes D-0005):**
    - any gesture that changes membership after import: "aggiungi all'incontro precedente", "separa", drag to reorder, merging `Incontro`s, moving a `Parte` between `Incontro`s;
    - overlapping or simultaneous `Registrazione`s. Two devices on the same meeting do not belong in the same `Incontro`; this is the user's choice at import, and nothing enforces it.
    
    The rename `Documento` → `Sbobinatura` shipped separately on main (D-0006, [ADR 0031](decisions/0031-rinomina-documento-sbobinatura.md)); no other term here is renamed.
  - `Eliminare una Registrazione` / "Elimina…" (`EliminaRegistrazione` → `RegistrazioneEliminata`) *(added 2026-09-25 [user], [ADR 0020](decisions/0020-elimina-registrazione.md))*. This is the user's **hard** delete of one `Registrazione` from its `Progetto`, and it cannot be undone. It removes:
    - the audio copied into the project;
    - every `Elaborazione` and the `Trascritto`;
    - the `Sbobinatura`;
    - every `Attribuzione` and `ImprontaVocale` of its `Voce`s.

    `ricorrente` `Parlante`s stay, with their prints from other recordings. An `occasionale` seen only there ceases to exist (INV-25). It is refused while an `Elaborazione` is `in_attesa` or `in_corso`: annullare it first, or wait until it ends. It is distinct from `Eliminazione del Parlante`, which leaves a tombstone. The original file outside the project is never touched. Not: cancellare, rimuovere, archiviare, nascondere (as distinct terms); scartare (reserved for the internal compensation of a failed import).

    *(amended 2026-09-30, feature `incontro` [user D-0003]; conflicts in part with ADR 0020 and ADR 0024, **for the architect**)* What eliminating a `Parte` means depends on the `Incontro`:
    - **The only `Parte` of its `Incontro`:** the `Incontro` ceases to exist and its `Riassunto` is deleted, as today.
    - It is also **the correction for a misplaced `Parte`** [user D-0008]: eliminate it, then import the file again into the right `Incontro`. That means a new transcription.
    - **A `Parte` of a multi-part `Incontro`:**
      - Its `Segmento`s leave the `Voce`s of the `Incontro`.
      - A `Voce` left with no `Segmento` goes, with its `Attribuzione` (then INV-25).
      - Every `ImprontaVocale` sourced from this `Registrazione` is purged (see `ImprontaVocale`).
      - The `Riassunto` of the `Incontro` is **not deleted**: it becomes `superato` and stays readable. The user accepted this privacy cost (D-0003). Text derived from the deleted audio therefore survives, and so do `Fonte`s that name the deleted `Parte`. This contradicts ADR 0020's [INV-28] ("no row keyed by its `registrazioneId` survives") and ADR 0024.
- **Notes:** audio decoding/normalization (format conversion, resampling) is a technical adapter inside `Trascrizione`, NOT a context and NOT part of `Registrazione`'s language.
- **Introduced by:** trascrizione-con-parlanti; **amended by:** incontro (2026-09-30: `Incontro`, `Parte`, `OraDiInizio`, import into an `Incontro`)

## Bounded context: Trascrizione
- **Role:** core — upstream of `Parlanti` and `Sbobinatura`; downstream of `Progetto`
- **Ubiquitous language:**
  - `Elaborazione` = one run of the local pipeline on a `Registrazione` (diarization + speech-to-text), long-running, with a `StatoElaborazione`. ~~v1: at most ONE completed `Elaborazione` per `Registrazione` — re-running it on a reviewed recording is not offered (retry only after `fallita`).~~ *(amended 2026-09-24 [user], [ADR 0018](decisions/0018-ritrascrivi.md))* Several may be `completata` (history); the `Trascritto` is the result of the latest one. A new one can start whenever none is open: "Trascrivi", "Riprova" after `fallita`, "Ritrascrivi" after `completata`. An `Elaborazione` still `in_attesa` (never started) can be annullata (see `Annullare`). Not: job, task, processing, analisi.
  - `StatoElaborazione` = `in_attesa | in_corso | completata | fallita`.
  - `Ritrascrivere` / "Ritrascrivi" *(added 2026-09-24 [user], ADR 0018)* = starting a new `Elaborazione` on a `Registrazione` that already has a `Trascritto`. The old `Trascritto` stays (read-only in S3) until the new run completes, and is then replaced whole: its `Voce`s are renumbered from 1 and the names given to them (`Attribuzione`s, prints) are lost. If the run fails or is annullata, nothing changes. Not: rielaborare, rifare, reset.
    *(amended 2026-09-30, feature `incontro` [user D-0002, D-0004])* Ritrascrivere acts on ONE `Parte`, and only that `Parte`'s `Segmento`s are replaced.
    - The `Voce`s of the `Incontro` lose that `Parte`'s `Segmento`s. A `Voce` left empty goes, with its `Attribuzione`.
    - A `Voce` that still has `Segmento`s in other `Parte`s **keeps** its `Attribuzione`. It loses only the `ImprontaVocale`s sourced from the re-transcribed `Parte`.
    - The new diarization of the `Parte` adds new, unattributed `Voce`s to the `Incontro`. They are joined to the existing ones as in spike `voci-tra-parti`.
    - **Numbering** [user D-0007]: a `Voce` number is **never reused** in an `Incontro`, not even when no `Voce` is left. A re-transcribed 1-part `Incontro` shows "Voce 4, Voce 5…" after "Voce 1–3". This amends today's "renumbered from 1" and ADR 0018 [INV-12]'s reuse across generations, **for the architect**.
    - The `Riassunto` of the `Incontro` becomes `superato`, **also for a 1-part `Incontro`** [user D-0007]. It is **not** deleted and **not** re-enqueued (D-0004, D-0007); this supersedes "`Riassunto` and `Ritrascrivere`" below.
  - `Annullare` (una `Elaborazione` in coda) *(added 2026-09-24 [user], ADR 0018 Amendment (b))* = withdrawing an `Elaborazione` that is still `in_attesa` (never started): it disappears and the `Registrazione` returns to its previous state (no `Elaborazione`, or its old `Trascritto`). A running (`in_corso`) `Elaborazione` cannot be annullata. Not: interrompere, fermare, abortire, cancellare.
  - `Numero di persone` (`NumeroPersone`) = how many people speak in a `Registrazione`, as stated by the user when starting an `Elaborazione` ("Trascrivi", or "Riprova" prefilled from the failed run). It is **optional**; when stated, it is an integer from **1 to 10**. It is carried by `AvviaElaborazione`, stored immutable on the `Elaborazione` it was given for, and passed to the `Diarizzatore` as the exact number of `Voce`s to form. When absent, clustering is automatic. It is a hint to diarization, NOT a count of `Parlante`s or of `Voce`s (the result may have fewer `Voce`s). User decision 2026-09-23, ADR 0014. Not: numero parlanti, numero speaker, num_clusters, partecipanti.
  - `FaseElaborazione` = the pipeline stage an `in_corso` `Elaborazione` is in: `decodifica | diarizzazione | trascrizione | allineamento` (displayed as "preparazione audio", "separazione voci", "trascrizione", "allineamento"). Progress information only, NOT guarded state: no invariant depends on it (INV-3 on `StatoElaborazione` unchanged). Not: step, stadio, progresso, avanzamento, passo.
  - `Trascritto` = the structured transcript of one `Registrazione`: the ordered `Segmento`s and the `Voce`s they belong to. **Source of truth** for the text (the `.md` is derived). Not: trascrizione (that is the context name), transcript, testo.
    *(amended 2026-09-30, feature `incontro`)* The `Trascritto` stays **one per `Registrazione`** (per `Parte`) and holds that `Parte`'s `Segmento`s. The `Voce`s they belong to are the `Incontro`'s, shared by all its `Trascritto`s.
  - `Voce` = a distinct voice detected by diarization inside ONE `Registrazione` (a cluster), labelled `Voce 1`, `Voce 2`… until attributed. It has no identity across recordings — that is `Parlante`'s job. Not: cluster, gruppo di voce, speaker, parlante anonimo, locutore.
    *(amended 2026-09-30, feature `incontro` [user D-0002]: scope widened from the `Registrazione` to the `Incontro`)*
    - **Meaning.** A `Voce` is a distinct voice of ONE `Incontro`, across all its `Parte`s: the "Voci dell'Incontro". The same person in part 1 and part 2 is **one** `Voce`, named once. Its `Segmento`s may lie in several `Parte`s. `Voce n` is unique inside the `Incontro`, and a number once used is never given again to another `Voce` of that `Incontro` [user D-0007].
    - **Birth.** The diarization of each `Parte` gives new `Voce`s to the `Incontro`, numbered after every number already used there. Joining two `Voce`s of different `Parte`s is `unire` (see `Revisione`), whether the user does it directly, through a `Proposta di unione`, or through whatever spike `voci-tra-parti` chooses. There is no second term for "the part of a `Voce` inside one `Parte`": it is the `Voce`'s `Segmento`s in that `Parte`.
    - **Identity.** It still has no identity across `Incontro`s; that stays `Parlante`'s job. A 1-part `Incontro`'s `Voce`s are today's `Voce`s.
  - `Segmento` = a time interval (start, end) of the `Registrazione` with its recognized text, belonging to exactly one `Voce`. Mixed IT/EN text in a single `Segmento` is normal (code-switching). Not: turno, battuta, utterance, frase, chunk.
    *(amended 2026-09-30, feature `incontro`)* A `Segmento` still belongs to ONE `Registrazione` (`Parte`), with its time relative to that file. It is identified within it. Its `Voce` is a `Voce` of the `Incontro`.
  - `Segmento confermato` *(added 2026-09-24 [user], [ADR 0019](decisions/0019-separazione-semi-automatica.md))* = a `Segmento` the user has placed or confirmed on its `Voce` by an explicit act (a manual move, a division, "Dai un nome a una frase"). It is never moved automatically. It carries no name. Not: frase bloccata, fissata, verificata.
  - `Revisione` = the user's correction of diarization errors on a `Trascritto`: **unire** two `Voce`s, **dividere** a `Voce` into two, **riassegnare** a `Segmento` to another `Voce`. Words of the text are NOT editable in v1. Not: correzione, editing, modifica.
    *(amended 2026-09-30, feature `incontro` [user D-0002])* `Revisione` now acts on the `Voce`s of an **`Incontro`**, across its `Parte`s. Examples: `unire` Voce 2 (part 1) with Voce 5 (part 2); `dividere` a `Voce` whose `Segmento`s span `Parte`s; `riassegnare` a `Segmento` to any `Voce` of the `Incontro`. `unire` across `Parte`s is how `Voce`s of different `Parte`s become one.
- **Notes:** the correction of *who a `Voce` is* (a wrong name) is NOT `Revisione` — it lives in `Parlanti` (`Attribuzione`). `Revisione` changes the structure (which segments belong together); `Attribuzione` changes the identity.
- **Introduced by:** trascrizione-con-parlanti; **amended by:** incontro (2026-09-30: `Voce` scoped to the `Incontro`, `Revisione` across `Parte`s, `Ritrascrivere` of one `Parte`)

## Bounded context: Parlanti
- **Role:** core (the differentiator: persistent identity per `Progetto` across recordings) — downstream of `Trascrizione` and `Progetto`; upstream of `Sbobinatura`
- **Ubiquitous language:**
  - `Parlante` = a real person's identity inside ONE `Progetto`, persistent across its `Registrazione`s; has a `Nome` and a `TipoParlante`. Not: persona, speaker, identità, partecipante, utente.
  - `Nome` = the display name of a `Parlante`, **unique among the `attivo` `Parlante`s of a `Progetto`**. Naming is optional: a `Voce` the user skips becomes an `occasionale` with the provisional `Nome` "Ospite del <DataRegistrazione>". Renaming changes only the displayed name everywhere (past `Sbobinatura`s regenerated), never the past diarization. Not: etichetta, alias, label.
    *(amended 2026-09-30, feature `incontro`)* "Ospite del <data>" takes the date of the `Incontro`, which is its first `Parte`'s `DataRegistrazione`. An unnamed guest who speaks in two `Parte`s is ONE `Voce` once joined, and so becomes ONE "Ospite del …", not two.
  - `TipoParlante` = `ricorrente | occasionale`. `occasionale` = a one-off guest whose `ImprontaVocale`s ARE kept and who can be proposed later and **promosso** to `ricorrente`. Behavioural difference: label, the provisional "Ospite del …" `Nome` for unnamed `occasionale`s, and `ricorrente` `Candidato`s ranked first in a `Proposta`. An `occasionale` left with no `Attribuzione` (e.g. after a re-attribution or a `Revisione`) ceases to exist — distinct from `Eliminazione del Parlante`: no tombstone (tactical INV-25). Not: ospite/fisso/guest/one-off as type names.
  - `StatoParlante` = `attivo | eliminato`. An `eliminato` `Parlante` is a **name-only tombstone**: it keeps its `Nome` (past `Trascritto`s/`Sbobinatura`s still show it) but has no `ImprontaVocale`, is never a `Candidato`, receives no new `Attribuzione` (sole exception: in `unire` the tombstone `Attribuzione` of the removed `Voce` is re-keyed onto the surviving one — tactical INV-21, ADR 0012 Amendment (b)), and its `Nome` becomes reusable by a new `Parlante`. Not: archiviato, disattivato, anonimizzato.
  - `ImprontaVocale` = a voice-print (embedding) of a `Parlante`, extracted from one attributed `Voce` (from a bounded selection of its `Segmento`s — `SorgenteImpronta`) of one `Registrazione`. A `Parlante` keeps SEVERAL (one per contributing `Voce`), never a single average. Biometric data of third parties, stored locally only. Not: voiceprint, embedding, firma vocale, profilo vocale.
    *(amended 2026-09-30, feature `incontro` [analyst, derived from ADR 0020 [INV-28] and ADR 0009; the architect confirms])* It is extracted from the `Segmento`s of one attributed `Voce` **in ONE `Parte`**, and never mixes audio of two files. A `Voce` that spans 3 `Parte`s can therefore source up to 3 prints. This keeps the purges exact:
    - eliminating or re-transcribing a `Parte` removes exactly the prints sourced from that `Registrazione`, whichever `Voce` they belong to.
    
    It still holds that prints are never averaged.
  - `Galleria` = the set of all `ImprontaVocale`s of a `Progetto`'s `Parlante`s, against which a new `Voce` is compared. Not: archivio, database voci, libreria.
  - `Proposta` = for one `Voce` of a new `Registrazione`, the ranked list (`ricorrente` first, then by `Fascia`) of `Candidato`s from the `Galleria`, shown with a `Fascia` and an `EstrattoAudio` — never a percentage. Not: suggerimento, match, riconoscimento, proposta di identità.
    *(amended 2026-09-30, feature `incontro`)* A `Proposta` is made for one `Voce` of an `Incontro`. The `Galleria` includes the prints from the other `Parte`s of the same `Incontro`. So a part-2 `Voce` can be proposed the `Parlante` just named in part 1. Confirming it gives two `Voce`s of the `Incontro` on the same `Parlante`, hence a `Proposta di unione`. This name-driven chain is one way (not the only one) to join `Voce`s across `Parte`s (spike `voci-tra-parti`).
  - `Candidato` = one `Parlante` inside a `Proposta`, with its `Fascia`.
  - `Fascia` = `forte | debole | nessuna` — the similarity band of a `Candidato`, from calibrated `SoglieFascia`. Not: punteggio, confidenza, percentuale, score.
  - `SoglieFascia` = the calibrated thresholds that turn similarity into a `Fascia` (output of spike `impronta-vocale-affidabilita`). Not: soglia di match.
  - `EstrattoAudio` = the ~10 s of audio of a `Voce` the user listens to before deciding: its longest `Segmento`s (≥ 1 s each, at most 3, ≤ 10 s total) concatenated (user decision 2026-09-23). For a `Candidato`, built the same way from the `Voce` that sourced one of its `ImprontaVocale`s. Not: snippet, anteprima, campione.
  - `Attribuzione` = the user-confirmed link `Voce` (of a `Registrazione`) → `Parlante`. Skipping a `Voce` counts as confirming it as a new `occasionale` ("Ospite del …"). Only confirmed `Attribuzione`s feed new `ImprontaVocale`s. Not: assegnazione, associazione, mapping, etichettatura.
    *(amended 2026-09-30, feature `incontro` [user D-0002])* It links a `Voce` **of an `Incontro`** to a `Parlante`. One `Attribuzione` names that person in every `Parte` of the `Incontro`, and in each of their `Sbobinatura`s.
  - `Eliminazione del Parlante` = privacy right: purges ALL the `Parlante`'s `ImprontaVocale`s (biometric data) from the `Galleria` and sets `StatoParlante = eliminato`; the `Nome` and past `Attribuzione`s survive, so past `Sbobinatura`s keep showing the name. Not: rimozione, cancellazione (as distinct terms).
  - `Frase di riferimento` *(added 2026-09-24 [user], ADR 0019 + Amendment (b))* = a `Segmento` of ≥ 1 s used as the voice sample of a `Parlante` in one `Registrazione`: its `Segmento confermato`s on the `Voce`s attributed to that person or, if there are none, every `Segmento` of those `Voce`s ("tutta la voce"). Derived, never stored. Not: campione, esempio, frase modello.
    *(amended 2026-09-30, feature `incontro`)* It is a sample of the `Parlante` in one `Incontro`, across its `Parte`s. "Riassegna per somiglianza" therefore compares within the whole `Incontro`. Whether similarity is reliable across files (another start, possibly another room) is measured by spike `voci-tra-parti`. If it is not, the scope falls back to one `Parte`, which is an open point for the tactical modeler.
  - `Riassegna per somiglianza` *(added 2026-09-24 [user], ADR 0019 + Amendment (b))* = the S3 action that compares every movable `Segmento` with each person's frasi di riferimento, shows a **preview** of the moves, and on "Applica" puts each one confidently similar to a person on that person's `Voce`. Nothing moves before "Applica". Not: auto-assegna, riconoscimento automatico, riclassifica.
  - `frase incerta` *(added 2026-09-24 [user], ADR 0019)* = a `Segmento` that "Riassegna per somiglianza" cannot place with confidence (too short, too similar to two people, or unlike everyone). It **stays where it is**. Not: frase dubbia, scartata.
  - `Proposta di unione` (`PropostaUnione`) = when two `Voce`s of the SAME `Registrazione` are attributed to the same `Parlante`, the app proposes (one click, never automatic, never blocking) to **unire** them via `Revisione`. Not: merge automatico, conflitto.
    *(amended 2026-09-30, feature `incontro` [user D-0002])* The scope is two `Voce`s of the SAME **`Incontro`**, in the same or in different `Parte`s. With it, the user joins a person across `Parte`s just by naming them. It is still never automatic.

    If spike `voci-tra-parti` chooses the print-based option, a second trigger may be added, **pending the spike**: two unattributed `Voce`s of different `Parte`s that are similar by print. That needs no name, which is the case of the unnamed guest. Its name, and whether it is the same term, is decided with the spike.
- **Introduced by:** trascrizione-con-parlanti; **amended by:** incontro (2026-09-30: `Attribuzione`, `Proposta`, `Proposta di unione`, `Frase di riferimento` scoped to the `Incontro`; `ImprontaVocale` sourced per `Parte`)

## Bounded context: Sbobinatura
- **Role:** supporting — downstream of `Trascrizione` and `Parlanti` (pure projection, owns no source of truth)
- **Ubiquitous language:**
  - `Sbobinatura` = the `.md` file of ONE `Registrazione` ("who says what"), **regenerated** from `Trascritto` + `Attribuzione`s + `Nome`s; never edited as a source, never parsed back. It lives in the project's `sbobinature/` folder. *(renamed 2026-09-30 from `Documento` [user], [ADR 0031](decisions/0031-rinomina-documento-sbobinatura.md): the term says what the file is, the transcript of who said what; a pre-rename project's `documenti/` folder is renamed on open)* Not: documento, export, file md, report, verbale.
    *(amended 2026-09-30, feature `incontro` [user, brief])* The `Sbobinatura` stays **one per `Registrazione`** (per `Parte`); there is no `Sbobinatura` per `Incontro`. It resolves each `Voce` to a `Nome` through the `Attribuzione`s of the **`Incontro`**. Its "Voce n" labels are the `Incontro`'s numbers, so the `Sbobinatura` of part 2 may show "Voce 4". A 1-part `Incontro`'s `Sbobinatura` is unchanged. The user-facing rename to "Sbobinatura" is a separate change (D-0006): the term stays `Sbobinatura`.
  - `Rigenerazione` = rewriting a `Sbobinatura` after its inputs change (end of `Elaborazione`, a `Revisione`, a new/changed `Attribuzione`, a `Parlante` renamed/deleted/promosso). Not: aggiornamento, riesportazione.
    *(amended 2026-09-30, feature `incontro`)* A `Revisione` or an `Attribuzione` on a `Voce` of the `Incontro` regenerates the `Sbobinatura` of **every `Parte`** where that `Voce` has `Segmento`s. Importing a new `Parte` into an `Incontro` changes no other `Parte`'s `Sbobinatura`: its `Voce`s are new.
- **Introduced by:** trascrizione-con-parlanti; **amended by:** incontro (2026-09-30)

## Bounded context: Sintesi
- **Role:** supporting — downstream of `Trascrizione`, `Parlanti` and `Progetto`; upstream of nothing (read only by the UI). It owns the `Riassunto`s and nothing else: it never re-models the transcript (it reads `Segmento`s through a consumer-owned port, like `Sbobinatura`), never writes the `.md`, never commands another context.
- **Ubiquitous language:** *(added 2026-09-25 by feature `sintesi` [user decisions + challenger RESHAPE])*
  - `Riassunto` = the result of summarizing ONE `Registrazione` with the local LLM, shown in the "Riassunto" tab of the recording page. It holds a `Sommario`, and lists of `Decisione`s, `QuestioneAperta`s, `Azione`s and `PuntoChiave`s, each with its `Fonte`s. At most ONE `Riassunto` is shown per `Registrazione`: the latest `pronto`. It is **never** part of the `Sbobinatura`, and the `Sbobinatura` never depends on it. Not: sintesi (that is the context name), summary, verbale, report, resoconto, minuta.
    *(amended 2026-09-30, feature `incontro` [user D-0001]; replaces "ONE `Registrazione`" everywhere in this context)*
    - **Scope.** A `Riassunto` summarizes ONE **`Incontro`**: all its `Parte`s, in order, as one input. At most ONE is shown per `Incontro`, and it replaces the per-`Registrazione` `Riassunto`.
    - **Migration.** Each existing `Riassunto` passes to the 1-part `Incontro` of its `Registrazione`, unchanged.
    - **Dependencies.** Spike `contesto-lungo` must close **before** the `Incontro`'s `Riassunto` is modeled or built, because a meeting is 1–3 h.
    - The rest of the definition is unchanged.
  - `StatoRiassunto` = `in_attesa | in_corso | pronto | fallito`. A new `Riassunto` starts `in_attesa`. While it runs, the previous `pronto` one stays shown; a `pronto` one **replaces** the previous whole; `fallito` changes nothing that was shown. Not: job state, stato elaborazione.
  - `Riassumere` / "Riassumi" = the request for a new `Riassunto` of a `Registrazione` that has a `Trascritto`, with an optional `Argomento`. It is made by the user, with ONE automatic exception: after a `Ritrascrivere` completes, a `Registrazione` that had a `Riassunto` gets a new "Riassumi" enqueued automatically with the same `Argomento` (user decision 2026-09-25). Nothing else re-summarizes on its own: not a first `Elaborazione`, not a `superato` `Riassunto`. Not: sintetizza, genera riassunto, rigenera, aggiorna.
    *(amended 2026-09-30, feature `incontro` [user D-0004])*
    - **What is summarized.** "Riassumi" asks for a `Riassunto` of an **`Incontro`**. It is accepted only when **every** `Parte` has a `Trascritto` and **no** `Elaborazione` of any `Parte` is open. This is the default proposed by the analyst, extending today's rule; the user did not object and may revisit it.
    - **The automatic exception is removed**, 1-part `Incontro`s included [user D-0004, D-0007]. After any `Ritrascrivere` the `Riassunto` becomes `superato` and waits for a manual "Riassumi di nuovo".
    - **Nothing re-summarizes on its own.** No `Riassunto` is ever re-summarized automatically.
  - `Argomento` = the short, optional text the user gives at "Riassumi" to say *di cosa si parla*. It drives the exclusion of what is `fuori tema`. It belongs to the `Riassunto` it was given for (kept with it, prefilled at the next "Riassumi"). Without an `Argomento` nothing is excluded. Not: contesto (that is a DDD word here), tema, prompt, descrizione, oggetto.
  - `fuori tema` = the part of a `Registrazione` unrelated to the `Argomento` (chit-chat, another project). It is left out of the `Riassunto`: it never appears as a `Decisione`, `Azione` or `PuntoChiave`. Not: off-topic, rumore, divagazione.
  - `Sommario` = the short prose (a few sentences) at the top of a `Riassunto`. A speaker it mentions (like one mentioned in the text of any element) is stored as a `Voce` reference and rendered with the current `Nome`, never as a literal name (user decision 2026-09-25). Not: riassunto breve, abstract, sintesi.
  - `Decisione` = something the speakers **agreed** on, with its `Fonte`s. Something only proposed, or left "da valutare", is NOT a `Decisione`. Not: delibera, conclusione, accordo.
  - `QuestioneAperta` = something proposed or discussed but **not agreed** ("da valutare", "ci pensiamo"), with its `Fonte`s. Kept apart from `Decisione` on purpose (challenger RESHAPE (4)). Not: proposta (that is a `Parlanti` term), da valutare (as a type name), ipotesi, pendenza.
  - `Azione` = something someone has to do after the `Registrazione`, with its `Fonte`s and an optional `Responsabile`. Not: task, todo, compito, cosa da fare (the UI label "Cose da fare" is allowed as text only), action item.
  - `Responsabile` = the `Voce` of the `Registrazione` who will carry out an `Azione`, or none. It is kept as a reference to the `Voce`, never as a name, so it shows the **current** `Nome` of whoever that `Voce` is attributed to ("Voce n" while unattributed). Not: assegnatario, owner, incaricato.
    *(amended 2026-09-30, feature `incontro` [user D-0002])* The `Responsabile`, a `PuntoChiave`'s speaker and every speaker a `Sommario` or an element's text mentions are `Voce`s **of the `Incontro`**. They are never qualified by a `Parte`: the same person is one reference across the whole meeting.
  - `PuntoChiave` = a relevant point of the discussion, possibly bound to who said it, with its `Fonte`s. Not: highlight, punto saliente, takeaway.
  - `Fonte` = the id of a `Segmento` of the `Trascritto` the `Riassunto` was made from, cited as the ground of an element. It is shown as the speaker (the `Nome` of the `Segmento`'s `Voce`, resolved at display) + the minute. Not: citazione, riferimento (taken by "Frase di riferimento"), source, prova.
    *(amended 2026-09-30, feature `incontro` [user brief])*
    - **What it is.** A `Fonte` = (`Parte`, `Segmento`). It is kept by the `Registrazione`'s identity, never by the numero della parte, which can change.
    - **How it is shown.** "parte 2 · 12:30": the numero della parte is derived at display, the minute is relative to that file, and the speaker is the `Voce` of the `Incontro`. A 1-part `Incontro` shows the minute only, as today.
    - **A deleted `Parte`.** A `Fonte` whose `Parte` was eliminated (D-0003) still exists in a `superato` `Riassunto`. How it is shown is a UX point.
  - `Verifica delle fonti` = the check applied to every LLM answer before a `Riassunto` becomes `pronto`: each `Fonte` must be an existing `Segmento` of that `Trascritto`, and a speaker the element binds (a `PuntoChiave`'s speaker, a `Responsabile`) must be a `Voce` of that `Trascritto` — for a `PuntoChiave`, one of the `Voce`s of its `Fonte`s. An invalid `Fonte` is **dropped**; an element left with **no valid `Fonte`** is dropped too and counted, **never shown as fact** (challenger RESHAPE (2)). Not: validazione, grounding, controllo citazioni.
    *(amended 2026-09-30, feature `incontro` [user brief])* The check is qualified **per `Parte`**. Each `Fonte` must name a `Parte` of the `Incontro` as read for the run, and a `Segmento` that exists in **that** `Parte`'s `Trascritto`. A bound speaker must be a `Voce` of the `Incontro`. For a `PuntoChiave`, it must be one of the `Voce`s of its `Fonte`s, which may lie in different `Parte`s. The drop and count rules are unchanged.
  - `superato` (`Riassunto superato`) = a `pronto` `Riassunto` whose `Trascritto` has changed **in structure** through a `Revisione` since it was made (unire, dividere, riassegnare — including "Riassegna per somiglianza"). It stays readable with a notice and a manual "Riassumi di nuovo"; it is **never regenerated automatically**. Renaming a `Parlante`, a new or changed `Attribuzione`, `Eliminazione del Parlante`, promotion, and confirming a `Segmento` do **NOT** make it `superato`: speakers are `Voce` references resolved to the current `Nome` at display (challenger RESHAPE (1), confirmed by the user 2026-09-25). Not: obsoleto, scaduto, stale, non aggiornato, invalidato.
    *(amended 2026-09-30, feature `incontro` [user D-0003, D-0004])*
    - **When.** An `Incontro`'s `pronto` `Riassunto` becomes `superato` when, since it was made:
      - any `Parte` is revised (a structural `Revisione`, across `Parte`s included);
      - any `Parte` is **re-transcribed** (`Ritrascrivere`);
      - the `Parte`s are **reordered** (a changed `DataRegistrazione`/`OraDiInizio`);
      - a `Parte` is **eliminated**;
      - a `Parte` is **added** (imported into the `Incontro`).
      
      This applies to every `Incontro`, 1-part included [user D-0007]. Any completed transcription of a `Parte` counts, a first one included.
    - **Never regenerated automatically**, whatever the cause. It stays readable, with "Riassumi di nuovo".
    - **The comparison.** A `Ritrascrivere` can reproduce identical ids, so being `superato` must be told from the ordered `Parte`s and the generation of each `Trascritto`, not from the `segmentoId → voceId` assignment alone. This is for the tactical modeler.
    - **Stale references** [user D-0007]. A `superato` `Riassunto` may reference `Voce`s that no longer exist: emptied by a `Revisione`, a `Ritrascrivere` or an elimination. Because `Voce` numbers are never reused in an `Incontro`, such a reference can never resolve to another person. It is shown as a **`Voce` no longer present**, never as a `Nome` and never as a live "Voce n". The exact wording is for UX.
    - The renaming, `Attribuzione`, promotion and `Eliminazione del Parlante` rules are unchanged: none of them makes it `superato`.
  - `Riassunto` and `Ritrascrivere` *(user decision 2026-09-25)* = a `Ritrascrivere` is NOT a `superato` case. When the new `Trascritto` replaces the old one, the `Riassunto` of that `Registrazione` is **deleted**, because its `Fonte`s and `Voce` references would point at a new generation, i.e. at the wrong people. A new "Riassumi" with the same `Argomento` is then enqueued automatically. A `Ritrascrivere` that fails or is annullata changes nothing.
    ~~(the rule above)~~ *(superseded 2026-09-30, feature `incontro` [user D-0004, D-0007])* A `Ritrascrivere` of any `Parte` **IS** a `superato` case, for every `Incontro`, 1-part included. The `Riassunto` is neither deleted nor re-enqueued, because a multi-hour re-summary must not jump into the shared FIFO on its own. A reference to a `Voce` of the old generation can no longer point at the wrong person, because numbers are never reused (see `superato`). This amends [INV-S8] ("no `Riassunto` outlives its `Trascritto` generation") and ADR 0021 §6: **for the architect**.
- **Constraints (user decisions 2026-09-25):**
  - Local LLM only, **bundled in the app** (no user-installed Ollama, no cloud): Qwen3.5 9B q4_K_M (Apache-2.0, 6.6 GB; *6,2 GB as shipped, ADR 0026 §8*), provisioned through `:modelli` like every other model (research `features/sintesi/research/scelta-modello-llm.md`). The runtime is llama.cpp in-process via JNI ([ADR 0026](decisions/0026-runtime-llm-jni-llama.md), spike `runtime-llm-in-app` closed).
  - Budget: a `Riassunto` of 1 h of audio (≈ 25k tokens) in **≤ ~5 min** on the M3 Pro (measured 175 s). Above ≈ 9–11 h (225 000 estimated tokens, the model's native 262k context; 2026-09-29, [ADR 0026](decisions/0026-runtime-llm-jni-llama.md) §5 amendment) "Riassumi" is refused with a plain message; the context is sized to each input.
    *(amended 2026-09-26 [user], [ADR 0026](decisions/0026-runtime-llm-jni-llama.md) §5–§6: keeping the 2500-word cap raises the budget to **≤ 10 min per hour** at the default cap (typical ≈ 3–4 min, measured 185 s) and the context to 40 960 tokens; the input limit stays 28 000 estimated tokens at ⌈characters ÷ 2.4⌉, ≈ 1 h 10 of audio.)*
  - A `Riassunto` never runs at the same time as an `Elaborazione`: summarizing and transcription share ONE serial execution (the `:avvio` queue), for memory and for the ADR 0011 time budget (challenger RESHAPE (3)).
  - Everything a `Riassunto` holds is meeting content. It is stored in the **`Progetto`'s SQLite database** like every other entity (ADR 0006/0010), not as separate files (user decision 2026-09-25: it is backed up with the project, it can be searched later, and there are fewer files). It is never sent anywhere.
  - The LLM model is **optional**: onboarding (S5) is unchanged, and the model is downloaded the first time the user asks "Riassumi" (user decision 2026-09-25).
  - `Elaborazione`s and `Riassunto`s share ONE **FIFO** queue, served in request order (user decision 2026-09-25).
  - Only the current `Riassunto` is kept: there is no history of replaced ones, and a queued `Riassunto` cannot be cancelled in the first release (user decision 2026-09-25).
  - Deleting a `Registrazione` (ADR 0020, pending on the sibling branch) deletes its `Riassunto`, queued ones included, for privacy. See Relationships `Progetto` → `Sintesi`.
    *(amended 2026-09-30, feature `incontro` [user D-0003]; conflicts with ADR 0020/0024, **for the architect**)* Eliminating the ONLY `Parte` deletes the `Incontro`'s `Riassunto`, as today. Eliminating one `Parte` of a multi-part `Incontro` makes it `superato` and keeps it readable. The user accepted that text derived from deleted audio survives.
  - *(added 2026-09-30, feature `incontro` [INV-I12 of the feature's tactical model])* The membership or order of an `Incontro` may change (import, elimination of a `Parte`, a date/time edit) while its `Riassunto` is `in_attesa` or `in_corso`.
    - A queued one reads the `Incontro` as it is when it starts.
    - A running one completes **born `superato`**, as with a `Revisione` during the run.
    - If the `Incontro` ceased to exist, nothing is written (INV-S8's compare-and-set).
  - *(added 2026-09-30, feature `incontro`)* The shared FIFO queue (ADR 0023) keys a `Riassunto` by its `Incontro`, no longer by a `Registrazione`, and the position shown follows. The input of an `Incontro` is the sum of its `Parte`s (1–3 h), under the ADR 0026 limit and budget (≤ 10 min per hour); spike `contesto-lungo` measures it. For the architect: the numbering reserved for `incontro` is the next free ADR (0031 on this tree) and migration `7.sqm` (to be checked against `main`).
  - Numbering reserved for `Sintesi`: ADRs from **0021**, and project-DB migration **`6.sqm`**.
- **Out of scope (later releases, not modeled):** *(amended 2026-09-30, feature `incontro`: the summary across the `Parte`s of ONE `Incontro` is now in scope; across `Incontro`s it is still out)* chapters of a `Registrazione`; the `Progetto`-level summary (across `Registrazione`s); clicking a `Fonte` to play the audio (the `Fonte` already carries what it needs); editing a `Riassunto`; putting it into the `Sbobinatura` (never); questions/chat over the transcript; **full-text search / indexing over `Riassunto`s and `Trascritto`s**. Search is a known LATER consumer, so the storage schema must not preclude it: the text is kept as queryable columns in the project DB, not as opaque blobs.

## Relationships
- `Progetto` → `Trascrizione` : upstream/downstream, Customer/Supplier — `Trascrizione` reads a `Registrazione` (identity + source audio) via a port; never writes the catalogue.
- `Progetto` → `Parlanti` : upstream/downstream — every `Parlante` and the `Galleria` are scoped by `Progetto` identity (no cross-project matching).
- *(amended 2026-09-25, [ADR 0020](decisions/0020-elimina-registrazione.md))* `Progetto` publishes `RegistrazioneEliminata`, and `Trascrizione` (veto + purge), `Parlanti` (purge + INV-25) and `Sbobinatura` (file removal, after commit) react to it. `Progetto` still never depends on them.
- `Trascrizione` → `Parlanti` : upstream/downstream, Customer/Supplier — `Parlanti` reads the `Voce`s of a completed `Trascritto` and their `Segmento` intervals (to extract `ImprontaVocale`s / `EstrattoAudio` and build `Proposta`s); it reacts to `Revisione` (voci unite/divise, segmento riassegnato) to keep `Attribuzione`s and `ImprontaVocale`s consistent. `Trascrizione` never knows names.
- `Trascrizione` → `Sbobinatura` : upstream/downstream, conformist — `Sbobinatura` renders the `Trascritto` as-is.
- `Parlanti` → `Sbobinatura` : upstream/downstream, conformist — `Sbobinatura` resolves each `Voce` to a `Nome` via `Attribuzione` (every `Voce` gets an `Attribuzione` — a skipped one becomes an `occasionale` "Ospite del …"; `Voce n` only while identification is not done yet; an `eliminato` `Parlante` still resolves to its `Nome`). The `Sbobinatura` is generated even if the user skips naming.
- `Trascrizione` → `Sintesi` : upstream/downstream, Customer/Supplier *(amended 2026-09-25, feature `sintesi`; was "future downstream consumer, not modeled")* — `Sintesi` reads, through its OWN consumer-owned port (same shape as `Sbobinatura`'s `LettoreTrascritto`/`SegmentoVista`: `segmentoId`, `voceId`, interval, text), the `Segmento`s of the current `Trascritto`, to build the LLM input, to run the `Verifica delle fonti`, and to tell when a `Riassunto` is `superato`. It also reads whether a `Trascritto` exists and whether a re-run is open ("Riassumi" is offered only when a `Trascritto` exists and no `Elaborazione` of that `Registrazione` is open). It **subscribes** to the published `TrascrittoSostituito` (ADR 0018): it deletes the `Riassunto` of that `Registrazione` and, once the replacing `Elaborazione` is committed, enqueues a new "Riassumi" with the same `Argomento` (user decision 2026-09-25). `Sintesi` never writes or commands `Trascrizione`; `Trascrizione` does not know `Sintesi` exists (it only publishes).
- `Parlanti` → `Sintesi` : upstream/downstream, conformist — `Sintesi` resolves each `Voce` (of a `Fonte`, of a `Responsabile`, of a `PuntoChiave`) to the current `Nome` through its OWN port (same shape as `Sbobinatura`'s `LettoreNomi`: `VoceRef` → `Nome`), at display time only. *(amended 2026-10-01, [ADR 0032](decisions/0032-riassunto-senza-nomi-nell-ingresso.md): the LLM input no longer carries Nomi — its legend always reads `V<n> = Voce n`, because with names the model returned no elements)* A `Riassunto` stores no `Nome` as its reference and no `ParlanteId`.
- `Progetto` → `Sintesi` : upstream/downstream — every `Riassunto` belongs to one `Registrazione` and is stored in its `Progetto`'s database. `Sintesi` **subscribes** to `RegistrazioneEliminata(registrazioneId, progettoId, titolo, dataRegistrazione, riferimentoAudio)` published by `Progetto` (ADR 0020 "Elimina registrazione", **pending on the sibling branch** `feature/trascrizione-con-parlanti`) and deletes every `Riassunto` of that `Registrazione`, including a queued one, which must then never run (privacy). A `Riassunto` completing on a deleted `Registrazione` writes nothing.
- `Sbobinatura` ⟂ `Sintesi` : **separate ways** — no relationship in either direction. The `Sbobinatura` is generated with or without any `Riassunto` and never waits for the LLM.
- *(added 2026-09-30, feature `incontro`)* **`Progetto` → `Trascrizione`, `Incontro` membership** : upstream/downstream, Customer/Supplier.
  - **What `Trascrizione` reads.** It reads, through its own port, which `Incontro` a `Registrazione` belongs to. That is fixed at import [user D-0008], so it never has to re-scope `Voce`s after a membership change. The `Voce`s it owns are scoped by that `Incontro`.
  - **What changes membership.** Membership changes only in two ways: an import adds `Parte`s, which then get their own `Elaborazione`s; and `RegistrazioneEliminata` removes one. On `RegistrazioneEliminata`, the existing synchronous `Trascrizione` subscriber (ADR 0020) now also removes the `Segmento`s of that `Parte` from the `Incontro`'s `Voce`s, and the `Voce`s left empty. It publishes the `Voce`-level consequences for `Parlanti`.
  - `Progetto` still never depends on `Trascrizione`.
- *(amended 2026-09-30, feature `incontro`)* **`Trascrizione` → `Parlanti`**: every `VoceRef` is now keyed by the **`Incontro`**, no longer by the `Registrazione`. `Parlanti` reacts to the `Voce`-level events `Trascrizione` publishes, as it does for `Revisione`:
  - it purges the `ImprontaVocale`s sourced from a re-transcribed or eliminated `Parte`;
  - it drops the `Attribuzione`s of `Voce`s removed;
  - it applies INV-25.

  It never reads `Progetto`'s membership to decide identity.
- *(amended 2026-09-30, feature `incontro`)* **`Parlanti` → `Sbobinatura`**: the name lookup is by `Voce` of the `Incontro`. A change on one `Voce` regenerates the `Sbobinatura`s of every `Parte` it spans.
- *(amended 2026-09-30, feature `incontro`)* **`Progetto` → `Sintesi`** becomes Customer/Supplier as well as the `RegistrazioneEliminata` subscription. `Sintesi` reads, through its OWN port, an `Incontro`'s ordered `Parte`s, which it needs to build the input, run the per-`Parte` `Verifica delle fonti` and tell `superato`. It learns of membership changes from the published events and never writes the catalogue.
- *(amended 2026-09-30, feature `incontro`)* **`Trascrizione` → `Sintesi`**:
  - `Sintesi` reads the `Segmento`s of **every `Parte`** of an `Incontro`, each keyed by (`Registrazione`, `Segmento`).
  - It reads whether each `Parte` has a `Trascritto` and whether any `Elaborazione` of the `Incontro` is open.
  - On `TrascrittoSostituito` of a `Parte` it no longer deletes and re-enqueues: the `Incontro`'s `Riassunto` becomes `superato`, for every `Incontro` (D-0004, D-0007).
- Execution (technical, not a domain relationship): the `:avvio` serial queue runs `Elaborazione`s and `Riassunto`s one at a time; `Sintesi` does not enter `Trascrizione`'s aggregates to use it.
- Single side (`app`): every boundary is `in-process` (port + contract test), no OpenAPI.

  - **Question.** How do the `Voce`s that the diarization of each `Parte` gives become the `Voce`s of the `Incontro`, so that the same person is ONE `Voce` across `Parte`s? The options:
    - **(a) print-based proposal confirmed by the user.** The `ImprontaVocale`-style similarity between `Voce`s of different `Parte`s yields a proposal to `unire`, one click and never automatic. It also covers unnamed guests.
    - **(b) joint clustering.** The prints of all `Parte`s are clustered together, and the join is automatic.
    - **(c) manual only.** `unire` across `Parte`s, plus the name-driven `Proposta di unione` that works without any spike.
  - **What the choice changes.**
    - (a) adds a read-model (a proposal between `Voce`s of different `Parte`s) and needs `SoglieFascia` calibrated **across files**. It overlaps spike `impronta-vocale-affidabilita`.
    - (b) makes the `Elaborazione` of a `Parte` `Incontro`-aware: the pipeline needs the other `Parte`s' prints. It changes what `Ritrascrivere` of one `Parte` does, and what a `Parte` imported later into an already-transcribed `Incontro` does (re-cluster, or fall back to (a)/(c)). It is also the only option with an automatic join, which a wrong join makes costly: a `dividere` across `Parte`s, and names on the wrong person.
    - (c) needs nothing new.
    - With every option, the join is `unire` (`Revisione`), and the language above holds unchanged.
  - **Closes when:**
    - on ≥ 2 real `Incontro`s in 2–3 `Parte`s with ≥ 2 people each, the same-person / different-person similarity across `Parte`s is measured;
    - for the candidate options, the correct / wrong / missed joins are counted, and the time is counted in the ADR 0011 budget;
    - the user judges the effort of joining the `Voce`s of a real `Incontro`, against the brief's outcome "nomina ogni persona una volta sola";
